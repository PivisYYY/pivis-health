# 待办与提醒

## 什么时候用
- 每次 `todo-add`、`project-set` 之前，先按本页定 `when`、`alarm`、`auto`、`until`。
- 老大说「提醒太多了」「别催了」「这个到点叫我」「算了」。
- 想用 `push` 主动找老大之前。

## App 怎么处理这些字段（照这个设计，不要另外安排提醒）
| 字段 | App 的行为 |
|---|---|
| 有 `when`，没有 `auto` | 到点发一次本地通知。打勾卡和练习视频卡 15 分钟后还没做，会自动再催一次 |
| 没有 `when` | 不响，只在页面上。没有时间、等着填的卡（fields、options、scale、number、proposal）排在最前面 |
| `auto:"bedtime"` | 不响。设备识别到入睡后自动打勾，summary 写入睡时间，老大可以更正。**目前只支持 bedtime** |
| `alarm` | 只对计时卡（timer）有效：老大点「开始」后，按 `duration_min` 倒计时（没有就按 alarm 时间）响系统闹钟，静音也会响。只用于午睡、闭眼歇 |
| `until` | 过了这个点还没处理就自动收起。proposal 卡一定要写 |
| `push` 命令 | 立刻推到锁屏。系统会拦：00:00–08:00 不推，每天最多 3 条，同一个 `--kind` 一天只推一次 |

## 怎么做
1. **数预算**：`./pivis-health todo-list`（不带 board，看所有板块），数今天还没做、带 `when`、没有 `auto` 的卡有几个时间点，再加上今天已经 push 的条数。
   - 老大自己要的提醒（「提醒我…」）照他说的排，不算进上限；你主动加的、他没要的提醒，一天最多 3 个时间点。`context-list --scope pref.remind` 里老大定的更少，就按他的。同一时刻别叠两个提醒，错开 5–10 分钟。
   - 同一个板块页面上，没做完的待办最多 3 件。
2. **超出预算时按优先级排**，排不上的去掉 `when`（`todo-update --id <id> --json '{"when":""}'`），卡还在页面上，只是不响：
   1. 安全相关（clinical-safety）
   2. 进行中项目的核心卡：CBT-I 的日记和睡前流程，训练日的训练开始卡
   3. 其他项目卡
   4. 临时加的卡
3. **按下表定时间**：
   | 卡 | when | 其他 |
   |---|---|---|
   | 睡眠日记 | 起床 + 20 分钟 | kind=fields |
   | 咖啡截止 | 不写 | kind=done，晚上打勾 |
   | 睡前流程 | 最早上床 − 60 分钟 | kind=follow，一个 follow 出的视频 |
   | 上床 | 最早上床 | `auto:"bedtime"`，不响 |
   | 训练热身 | 开始 − 10 分钟 | follow，一个视频 |
   | 练完记录 | 单次活动写结束时间；项目里不写 | fields |
   | 称重 | 不写 | number |
   | 饭的照片 | 不写（老大要提醒才写饭点） | fields，photo |
   | 呼吸练习 | 老大选的时间 | follow，一个视频 |
   | 提议、复盘 | 不写 | proposal，写 until |
   | 午睡、闭眼歇 | 老大定的时间 | timer，`alarm` = 开始 + 时长 |
4. **时段**：会响的卡不排在 `pref.remind` 里老大说别打扰的时段，也不排在 00:00–08:00。老大自己定的睡前流程、起床后的日记除外。
5. **提醒还是闹钟**：要老大「记得做」的用 `when`（通知可以忽略）。必须准时停下来的（午睡结束）用 `alarm`。早上起床不用 `alarm`，请老大用手机自己的闹钟。
6. **自动打勾优先**：设备能识别的（现在只有入睡），用 `auto`，不让老大手动点。训练、步数还不能自动打勾，用记录卡。
7. **文字**：title 不超过 14 个字，写要做的事。note 不超过 16 个字，只写有信息量的一句（「在床外做，床只用来睡」），不写操作说明（「做了就点一下」）。

## 错过了怎么办
- App 会自动再催一次（15 分钟后），**你不再催，也不 push**。
- 过期或跳过的卡：不补到今天，不加补偿任务。第二天按 habit-coach 的「不连续漏两次」处理。
- 例外：安全相关的事（比如老大说过胸闷、要复诊），可以在对话里再说一次。

## 老大说「算了」
卡上没有「晚点」「算了」按钮。老大会在对话里说，常常是点卡上的 P-Health 图标带着这张卡来的（消息开头【待办 <待办 id> · <标题>】），改的就是这一张。要改时间就 `todo-update --id <id> --json '{"when":"21:30"}'`，只改这一张。
1. 这张卡：`todo-update --id <id> --json '{"status":"skipped","summary":"老大说算了"}'`。
2. 今天其他同类的卡（同一板块、同一主题）：去掉 `when` 或者也标 skipped。今天不再提这件事，也不 push。
3. 第二天照常，不追问「昨天为什么算了」。CBT-I 例外：第二天的日记照常检查规则（见 cbti）。
4. 老大说「以后都不要」：`context-record --scope pref.remind`，payload 写进 rule，再 project-set 去掉对应模板的 `when` 或整项。附 receipt。

## push 什么时候用
- 只在这两种情况用：数据里出现今天就要处理的红旗（`--level see_doctor` 或 `alert`）；或者老大要你在某个时间主动找他，而这件事不适合做成待办。
- 不用 push 催错过的待办，不用 push 发鸡汤或日报。
- `./pivis-health push --title "P-Health" --body "<一句话>" --page <sleep|sport|stress|today> --kind <固定的 key>`。返回 skipped 就停，不换 key 重试。

## 规则与红线
1. 老大自己要的提醒（「提醒我…」）照他说的排，不算进上限；你主动加的、他没要的提醒，一天最多 3 个时间点（带 when 的卡 + push）。push 系统另外限每天 3 条。
2. 每张卡最多一次到点提醒 + 一次 App 自动催，不加第三次。
3. 老大说「算了」，当天同类事不再提，不叠加补偿任务。
4. 老大定过：勿扰和开车时不推。不要设计开车时响的卡。

## 模板
到点提醒（会响）：
```json
{"board":"sleep","when":"23:30","title":"床外拉伸","kind":"follow","note":"在床外做，床只用来睡",
 "media":{"kind":"video","title":"睡前拉伸 · 10 分钟","url":"/media/follow/<ssid>/out.mp4","duration_min":10}}
```
不响的记录卡：
```json
{"board":"life","title":"早上称一下","kind":"number","note":"空腹、上完厕所",
 "inputs":[{"id":"kg","label":"体重","type":"number","unit":"kg","submit":"agent"}]}
```
设备自动打勾：
```json
{"board":"sleep","when":"00:30","title":"00:30 后再上床","kind":"done","auto":"bedtime","note":"困了再上床"}
```

## 成长
- `pref.remind`：`{"rule":"每天最多 2 次提醒，上午工作时不打扰","max":2,"quiet":["上午工作时"]}`。
- `learn.remind`：哪个时间点的卡老大最常做、最常跳过。例：`{"rule":"21:00 的卡常过期，22:30 的能做到","evidence":"近 2 周 todo-list"}`。下次排时间先看这条。
