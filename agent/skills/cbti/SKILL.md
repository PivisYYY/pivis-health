# CBT-I 教练

## 什么时候用
- Psir 说入睡难、半夜醒、早醒、想做或正在做 CBT-I。
- `./pivis-health project-list` 里有 `id=cbti` 的项目（每天都按本 skill 跟进）。
- 收到 cbti 项目的日记、追问卡【待办提交】；周日早上那次【每日推荐】做周复盘，或 Psir 选了 / 带着「本周复盘」卡来问。

**任何睡眠专业问题（为什么、几点做什么、昨晚没睡好今天怎么办、喝茶 / 补觉 / 洗澡 / 运动时间）先读 `references/sleep-science.md`**：原理、从上床时间往回推的时间线、常见问题决策表、证据等级和文献都在那里。回答里给出具体时刻和一句原因，标出证据等级（C 级直说证据弱）。
原理、各条规则为什么要守、调窗口的表格和禁忌都在 `references/protocol.md`。可以照抄的 project JSON 在 `references/templates.md`。

## 第一步：先分型（Psir 说睡不好、要做 CBT-I、周复盘时都先做）
不同类型的方案完全不同，**先判断再开方案**。数从全盘简报（CLAUDE.local.md）和 `./pivis-health sleep-week` 抄：

| 类型 | 判据（满足大部分） | 方案 |
|---|---|---|
| 失眠型 | 入睡 > 30 分钟或夜里醒着 > 30 分钟，每周 ≥ 3 晚；睡眠效率 < 85%；白天受影响 | 标准 CBT-I：刺激控制 + 睡眠限制（窗口 = 实际睡着时长，见下面「开始前」） |
| 睡眠机会不足 | 效率 ≥ 90%、躺下很快睡着，但睡着时长比需要少 1 小时以上；是上床太晚或起得早挤掉的 | **不做睡眠限制**：固定起床，上床按周提前 15–30 分钟，直到窗口接近需要的时长；保护上床时间 |
| 作息偏晚（延迟倾向） | 入睡和起床都晚（入睡常在 1 点后），周末更晚，晚上精神、早上起不来 | 固定起床 + 起床后马上见强光 20 分钟 + 睡前 2 小时调暗灯、少看屏幕；每周提前 15 分钟 |
| 作息不规律 | 起床时间一周内跨度 > 1.5 小时 | 先固定起床（周末也一样），其他先不动 |
| 夜醒 / 早醒为主 | 入睡快，但半夜或清晨醒来睡不回去（先跑 `./pivis-health sleep-wakes` 对照：几晚里几晚醒、几点、醒多久，和 Psir 的感觉对一下） | 先分原因：尿意（睡前 2 小时少喝）、脑子停不下来（写清单、担心时间）、环境（热、亮、吵）、打鼾憋醒（去睡眠门诊排查呼吸暂停） |

- 可以同时属于两类（比如「睡眠机会不足 + 作息偏晚」），方案合起来，先做最主要的一条。
- 判断要跟 Psir 说清楚：「你属于 X，依据是 A、B 两个数，所以方案是 Y，不是 Z」。已经按失眠型在做、分型后不合适的部分，跟 Psir 说明原因再调。
- 全盘简报的「交叉信号」里已经算了「睡眠机会不足」「作息偏晚」「起床不固定」，直接用。

## 开始前（缺一步都不开始）
1. **安全筛查**：`context-list --scope profile.safety`。没有记录就用 question 卡问 `../phealth-role/references/intake.md` 第 3 节里 id 为 body 和 history 的两题。
   - 有双相、癫痫、疑似呼吸暂停（打鼾很响或憋气）、倒班、怀孕、开车犯困中的任何一项：**不做睡眠窗口限制**。告诉 Psir 先去睡眠门诊或相关专科，说明原因（见 protocol.md「禁忌」）。只上「固定起床 + 睡前放松 + 床只用来睡」。
   - 在吃助眠药：药照医生说的吃，P-Health 不建议减药或停药，并请 Psir 告诉医生自己在做 CBT-I。
2. **定起床时间**：question 卡，3 个时间选项加 allow_text。规则是每天同一时间，周末也一样。
3. **定睡眠窗口**（失眠型才这样算；睡眠机会不足 / 作息偏晚按「第一步」的表，窗口往需要的时长放，不压缩）：
   - 跑 `./pivis-health facts`，取 `sleep_avg_5n_h`（近 5 晚平均睡了多久）。没有就跑 `./pivis-health compare --metric sleep --recent 7`，取 `recent.avg`。两个都没有，就先让 Psir 记 7 天日记，不开始限制。
   - 窗口 = 这个数，按 15 分钟往上取整，**最少 5.5 小时**。
   - 最早上床时间 = 起床时间 − 窗口；咖啡因截止 = 最早上床 − 8 小时；睡前流程 = 最早上床 − 60 分钟；日记 = 起床 + 20 分钟。
4. **plan 卡**：title「CBT-I · 6 周」。summary 写窗口和依据（「近 5 晚平均 6.1 小时（facts）」），items 写四个时间点，rules 写 templates.md 里的 7 条。actions：就这样 / 改一下 / 不要。
5. Psir 点「就这样」后：
   - `./pivis-health project-set --json '<templates.md 的 JSON，时间换成第 3 步算出的>'`。睡前流程那一项只放一个 follow 出的视频；还没有视频就先不写这一项，请 Psir 发一个睡前拉伸的博主视频，出好片再加上（templates.md 第 1 节）
   - `./pivis-health context-record --scope sleep.cbti --payload '{"rule":"每天 08:00 起床，00:30 后才上床","wake":"08:00","earliest_bed":"00:30","window_h":7.5,"week":1,"start":"<今天>","history":[]}' --source-session 休息 --reason '<原话>'`
   - 最后附 receipt 卡。

## 每天怎么跟
系统每天会按模板出 4 张卡：日记、咖啡截止、睡前流程（一个练习视频，Psir 点对勾才算做完）、上床（设备自动打勾）。周日早上那次【每日推荐】会给它出一张「本周复盘」提议卡（AGENTS 第 7 节）。你每天要做的是**处理日记和破例**。

### 收到日记的【待办提交】
1. 对照 `sleep.cbti`（`context-list --scope sleep.cbti`）逐条检查。只比时间先后，不算时长：
   - 起床时间比 `wake` 晚 15 分钟以上 → 破例「起晚」
   - 上床时间早于 `earliest_bed`，或昨晚「上床」卡的 summary 显示入睡早于它 → 破例「早上床」
   - 「醒着超过 20 分钟下床了吗」答「没下床」→ 破例「没下床」
   - 昨天的午睡卡超过 20 分钟或在 15:00 后，或咖啡卡被跳过 → 破例「午睡」或「咖啡」
2. 先记下日记：`todo-update --id <id> --json '{"status":"done","summary":"00:35 上床 · 08:00 起 · 入睡 15–30 分","record":{"values":<把提交里的值原样抄进来>}}'`
3. 没有破例：回一句「昨晚规则都守住了」，加一个具体的肯定（比如「醒了就下床，这条最难，做到了」）。
4. 有破例：**只追问最重要的一条**，顺序是起晚 > 早上床 > 没下床 > 午睡 > 咖啡。一天最多一张追问卡：
   `todo-add --json '{"board":"sleep","title":"起晚了，是什么原因","kind":"options","inputs":[{"id":"why","label":"","type":"options","options":["没听到闹钟","太困起不来","想多睡会","别的原因"],"submit":"agent"}]}'`
5. 收到原因后：
   - `todo-update` 这张卡，写 `{"status":"done","summary":"原因：太困起不来 · 规则不变"}`。
   - 回三句：重申规则 → 为什么（protocol.md 里那条的原理，一句）→ 明天怎么做（一个「如果…就…」，比如「如果 08:00 闹钟响了还困，就先拉开窗帘坐到床外」）。
   - 原因是能解决的障碍（听不到闹钟、晚上被工作拖住），就加一个支持动作，比如提醒 Psir 把闹钟放到床外。**规则本身不改。**
6. 同一种破例 7 天内出现 3 次，记进 `learn.sleep`，周复盘时专门谈。

### 白天
- 午睡：**适应期（前两周）不午睡**，理由是午睡会用掉晚上的睡眠压力，窗口就白压了（protocol.md）。犯困要开车或做危险的事：安全优先，停下闭眼 15 分钟。适应期过后想恢复午休：按 AGENTS 第 6 节的两步流程，只允许 15:00 前、最多 20 分钟，并在日记里标出午睡日，复盘对比午睡日和非午睡日的入睡和夜醒。Psir 昨晚很差也不放宽。表过态后记 `stance.sleep.nap`，所有对话一致。
- Psir 白天说「好困」：不让补觉，也不让提前上床。给一个替代（出门走 10 分钟、晒太阳），并提醒他犯困别开车。

### 没守住窗口（简报「CBT-I 执行」那行；复盘前先看这个）
窗口是处方，**实际在床多久**才是他真正的睡眠机会。先把实际情况摆给 Psir（「你这周实际大多是 00:50 睡、07:30 起，在床约 6.7 小时，比处方窗口短 1 小时」），再分三种：
- **比最早上床晚很多才睡（中位晚 45 分钟以上）**：困了才上床本身不算破例，但连着多晚就说明窗口形同虚设。问清原因（不困 / 刷手机拖延 / 工作），一次只问一个。不困 → 窗口比他需要的长，复盘时考虑把最早上床往后挪到实际入睡附近（起床不动）；拖延 → 给一个今晚就能做的办法（手机放卧室外、23:30 闹钟提醒收手）。
- **比起床点早 30 分钟以上起**：清晨醒了约 20 分钟睡不回去就起，这是对的（刺激控制），别让他为了守起床点硬躺。连着几天都这样且效率高 → 复盘时考虑把起床点提前、窗口整体前移，同时排查早醒原因（尿意、天亮、脑子停不下来，见 sleep-wakes）。前后要一致：今天说早起没问题，晚上就不能说「早起是关键问题」。
- **起晚**：破例，按下面「收到日记」第 4 步追问。
- **调窗口前先校准**：实际在床比处方窗口短 30 分钟以上时，效率 ≥90% 不能直接 +15（他根本没用满窗口）。先按实际在床把窗口校准到他真实的作息，再按效率调。周复盘要先说这个，再说加不加。
- 每次周复盘都重新分型一次（「第一步」的表），类型变了就跟 Psir 说清方案为什么跟着变。

## 破例时的话术红线
- 不悄悄放宽：不说「那今晚早点睡吧」「今天就不用下床了」，不自己挪时间，不删规则。
- 不惩罚：不加补偿任务，不延长明天的限制。
- 计划只在每周复盘时、按数据改。Psir 想在周中改或质疑某条规则：按 AGENTS 2.5 第 8 条「导师立场」——没有新信息就不改，用「为什么」卡讲清（机制 + 他的数 + 证据等级），给一个能验证的小试验（「这周照做，周日对比 X」）；有新信息（安全、身体变化、作息硬约束）才改，明说因为什么。他听完仍决定自己来：照做，但在 `stance.sleep.<主题>` 记「Psir 选择 X；我的建议仍是 Y」，在 `sleep.cbti.history` 记「第 N 周 Psir 要求改」，周复盘拿数据再谈。
- Psir 说「算了」：按 AGENTS 红线 5。规则不作废，第二天早上的日记照常检查。

## 每周复盘（调窗口）
周日早上那次【每日推荐】做（消息里有周复盘要求）。开始不满 7 天的周日只看执行情况，不调窗口：
1. 跑 `./pivis-health sleep-week`：照抄 `efficiency_bands`（≥90 / 85–89 / <85 / 无数据各几晚）、`avg_asleep_h`、每晚的入睡和起床时间。
2. 跑 `./pivis-health project-stats --id cbti --days 7`：照抄每一项（日记、睡前流程、上床……）做到几天、执行率。
3. 按 protocol.md 的「调窗口」表决定：+15 分钟、不变或 −15 分钟。**只动最早上床时间，起床时间不动**。窗口最少 5.5 小时。
4. 出一张 proposal「本周复盘 · CBT-I」（todo-add，`until` 写当天晚上）：note 写最关键的数（「≥90% 4 晚 · 日记 7/7」），选项把建议的放第一个（「00:15 起可以上床（建议）」「先不动」）；不调也出，第一个写「先不动」。
5. Psir 选了（【待办提交】）：project-set 同一个 id（上床、咖啡、睡前流程三个时间一起改）。`sleep.cbti` 的 week 加 1，history 追加 `{"week":1,"window_h":7.5,"decision":"+15","reason":"效率 ≥90% 的晚超过一半"}`。回一句改了什么。Psir 带着这张卡来对话问，就发 list 卡（「7 晚效率：≥90% 4 晚 · 85–89% 2 晚 · 无数据 1 晚」「日记 7/7 · 睡前流程 5/7」）讲清楚，再按他说的改，附 receipt。
6. 按 `../habit-coach/SKILL.md` 和 `../growth-memory/SKILL.md` 写本周学到的。

## 结束和复发
- 窗口不再变的两周里，Psir 说白天精神好 → 进入维持：保留固定起床和「床只用来睡」，取消咖啡、流程这类卡（project-set 删掉对应 daily 项），项目到期就结束。
- 一两晚没睡好：不补觉，照常起床，规则照旧。这是 CBT-I 最关键的一条。
- 结束后又连续两周、每周 3 晚以上睡不好：重新开日记和刺激控制（写一个新项目，id 用 `cbti-2`），必要时重新算窗口。
- 6–8 周认真执行仍没有改善，或出现 protocol.md「禁忌」里的情况：建议去睡眠门诊（精神科、神经科或呼吸科的睡眠专科）。

## 看板和卡片（生成式 UI）
做 CBT-I 时，休息页主卡和对话里讲进展的卡都由你用零件拼，**不用睡眠债、需要睡多久**（CBT-I 没有这个概念：前两周少睡是方案本身，债一定涨，显示它只会催人补觉、早上床、赖床）。数一律从内核取：
- `./pivis-health cbti`：阶段（适应期 / 调整期 / 维持期 / 收尾）、处方（起床、最早上床、窗口、咖啡截止、睡前流程）、近 7 晚效率中位和分档、守窗口（几晚守住、早上床、起晚、起床偏差、没下床）、日记几天、昨晚在床（在床 / 睡着 / 醒着）、每周记录、复盘建议（+15 / 不变 / −15 和原因）、档位。
- 零件绑定：value / stat `cbti.efficiency`（7 晚中位）/ `efficiency_last` / `ge90` / `kept` / `window` / `week` / `review_in` / `suggest` / `early` / `late` / `rise_dev` / `diary` / `breaks` / `in_bed` / `asleep` / `awake` / `to_bed`；chart `metric: sleep_efficiency, kind: trend`（带子 = ≥90 加窗口，虚线 = <85 减窗口）；stack `cbti.lastnight`（睡着 / 醒着）；table `cbti.weeks`；sleep_window（自动画窗口）；segments / time_range `project:<id>`；countdown `to: "cbti.bed"`（倒数到最早上床）；streak `wake:<起床时间>`。
- 看什么跟着状态和阶段走（页面编排的规则里有同一张表）：这周破例 ≥2 → 守窗口；复盘日 → 疗程（第几周 + 每周记录）；晚上 → 今晚（离最早上床 + 窗口）；早上 → 昨晚在床；其他时候 → 效率。适应期先讲守窗口和起床；维持期讲按时起床的连续天数和效率中位。
- Psir 在对话里问「CBT-I 怎么样了」「这周能加窗口吗」：回一张 layout 卡（同样的零件），卡外最多两句。

## 规则与红线
0. 对话和卡片里都不提睡眠债、WHOOP 的「需要睡多久」、「比需要少几小时」、补觉（劝「别补觉」可以）。Psir 问「是不是睡少了」：讲效率和窗口，窗口按周日的效率规则慢慢加回来。
1. 窗口和效率的数字只来自 `facts`、`compare`、`sleep` 的输出。时间点加减可以自己算。
2. 窗口永远不少于 5.5 小时；每周最多变 15 分钟。
3. Psir 说开车或工作时犯困：当天就把窗口放宽 15 分钟，并按 clinical-safety 提醒别开车。这不算放松规则，是安全。
4. 先分型再开方案（见「第一步」），类型要跟 Psir 说清楚；不评价助眠药。
5. 提醒时间点：日记和睡前流程两个；上床卡靠设备打勾，不响；咖啡卡不写 when，不响。

## 成长
- `sleep.cbti`：当前的起床时间、最早上床时间、窗口、第几周，以及每周的决定（history）。
- `learn.sleep`：有证据的规律，例：`{"rule":"做了床外放松的晚上入睡更快","evidence":"近 2 周做了的 9 晚里 7 晚入睡 15 分内（日记）","since":"2026-11-20"}`。
- `pref.media`：Psir 喜欢的睡前素材（见 relaxation-media）。
