# 接入 DSH（P-Health Agent）

P-Health Agent 跑在本机的 DSH（DeepSeek Harness）上。本文说明 App、服务端和 Agent 之间怎么连。地址、令牌、密钥都在本机配置里，不进仓库。

## 会话

| 会话 | 用途 |
|---|---|
| 主对话 | App 底栏中间的入口；每日推荐也发到这里 |
| 休息 / 运动 / 压力 | 三个板块各一个对话，从哪个板块点开就带哪个板块的上下文 |
| 事件处理 | 接收手机上报的场景事件，含义由 P-Health 判断 |
| 页面编排 | 每次编排开一个轻量会话：单独的工作目录和预设，不带聊天人设和工具，只按格式出 JSON |

所有聊天会话建在同一个 Agent 预设上，共用同一个工作目录、同一套 `./pivis-health` 命令和同一份记忆。

## Agent 的规则和技能

- 规则：[`agent/AGENTS-v3.md`](../agent/AGENTS-v3.md)。装到工作区时，在后面接上本机的个人附录（不进仓库），生效的偏好、纠正过的要点、了解到的你由 `prefs-sync` 单独写进同目录的 `AGENTS.local.md`：DSH 按文件刷新指令，记一条偏好只补这一小份，不用把整份规则再发给每个对话。
- 技能：[`agent/skills/`](../agent/skills)，DSH 直接从仓库读。专业资料在各技能的 `references/` 里。
- Agent 的工具：命令行（只用来跑 `./pivis-health`）、读写自己的工作目录、技能。它不能改 `~/Tools` 下的程序和工具，不读数据库和源码，不建定时任务，不用飞书。

## 对话链路

1. App 带设备密钥向服务端要 DSH 的登录令牌（`/api/dsh-token`，只给本机和带密钥的 App）。
2. 发消息：App 直接调 DSH web 的 `session/prompt`（排队模式）；会话还不存在时服务端先建好（`/api/chat/send`）。
3. 收回复：WebSocket 一句一句流回来；历史从服务端的 `/api/chat` 读（服务端解压会话文件，滤掉系统注入的约定和时间快照，照片路径换成缩略图标记）。
4. 回合进行中，状态接口带上 P-Health 正在跑的命令，App 显示成"看今天的待办"这类话。

## 服务端主动发给 Agent 的消息

| 消息 | 什么时候 | Agent 怎么做 |
|---|---|---|
| 【每日推荐】 | 每天 08:00、13:00、18:00 | 推荐 1–2 件事写成待办卡；早上那次顺带做每日整理，周日那次做周复盘 |
| 【待办 …】/【习惯 …】 | 你点了卡上的 P-Health 图标 | 按这张卡的上下文回答、改时间、记原因 |
| 页面编排 | 编排节拍、改了项目或偏好之后 | 在编排会话里出页面 JSON，服务器校验，不过就退回改（最多 3 轮） |
| 场景事件 | 事件分发每 30 秒 | 判断要不要行动；开车时不即时打扰 |

## 隔离的测试环境

模拟、演示、封版测试环境用环境变量把 Agent 的工作目录和会话前缀换掉（`PIVIS_DSH_CWD`、`PIVIS_DSH_PREFIX`），和真实会话完全隔开；这些环境里不推送。iOS 模拟器上的 App 用启动参数选环境。
