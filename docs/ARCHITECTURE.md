# 架构与开源范围

## 当前状态（2026-11）

内核、服务端和 Agent 规则都已经在本仓库里，iOS 客户端在单独的仓库。本文说明各部分怎么分工，以及哪些不公开。

## 数据流

```text
Apple 健康 ──(App 每次打开上报当天聚合 + 睡眠分段)──┐
WHOOP 官方 API ──(whoop-sync 每小时，14 天滚动快照)──┤
                                                      ▼
                    只读数据层（同一样本跨 App 重装只算一次）
                                                      ▼
              确定性计算：睡眠重建 · 个人基线 · 7 种主卡图表 · 数据新鲜度
                                                      ▼
        ┌──────────── 证据（数值、能画的图、项目、待办、偏好）────────────┐
        ▼                                                                    ▼
  页面编排（P-Health 写页面 JSON → 服务器校验 → 发布）          对话（P-Health 调命令查数、改待办、记偏好）
        └──────────────────────────────┬─────────────────────────────────┘
                                       ▼
                    iOS App：页面 · 生成式待办 · 对话 · 提醒
                    （轮询 /api/v3/status：哪块在改就框住哪块，改好自动换上）
```

## 分层约束

| 层 | 在哪 | 边界 |
|---|---|---|
| 数据 | `readonly.py`、`whoop.py`、`whoop_sync.py` | 客观库只读；WHOOP 和 Apple 的同名指标口径不同，一条序列只取一个设备；断更就如实说 |
| 计算 | `sleep.py`、`baselines.py`、`viz.py` | 数字只从这里出；常态范围按本人近 30 天算，不是医学标准 |
| 编排 | `v3.py`（证据、校验、发布）、`agent/AGENTS-v3.md` | Agent 只能引用证据里的数，不能自己写数；校验不过的页面不发布 |
| 待办与习惯 | `todos.py` | 待办内容由 Agent 生成；习惯项目按模板每天展开，改模板"今晚起"生效 |
| 偏好与记忆 | `prefs.py`、`agent_context.py` | 一份共享记忆，页面编排和对话都读它 |
| 接口 | `web.py`、`cli.py` | App 走 HTTP；Agent 走 `./pivis-health` 命令 |
| 示例与测试 | `examples/`、`tests/` | 只用合成数据，不连接真实健康库 |

## 不公开 / 不入库

- 本机配置（`config.local.json`）、地址、APNs 密钥、WHOOP 凭据和令牌。
- 真实健康数据库、WHOOP 快照、餐照与试纸照片、聊天记录。
- 带个人信息的 Agent 规则附录（`agent/AGENTS-real.md`）。
- 安装包（`install/*.ipa`）。

## 不做的事

- 不做疾病风险、身体年龄或临床效果的验证声明。
- 不把工程上的异常筛选说成诊断。
