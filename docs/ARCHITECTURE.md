# 架构与开源范围

## 当前状态（2026-11）

内核、服务端、Agent 规则和 iOS 客户端都在本仓库里（App 在 [`ios/`](../ios/)）。跟练出片工具 pivis-follow 是本机的独立工具，不在本仓库。本文说明各部分怎么分工，以及哪些不公开。

## 数据流

```text
Apple 健康 ──(App 每次打开上报当天聚合 + 睡眠分段)──┐
WHOOP 官方 API ──(whoop-sync 每 15 分钟，并按天存档)───┤
手机场景事件 ──(定位、蓝牙、摘手环，幂等入库)──────────┤
                                                      ▼
                    只读数据层（同一样本跨 App 重装只算一次）
                                                      ▼
     确定性计算：睡眠重建 · 个人基线 · 7 种主卡图表 · 55 个画布零件 · 项目执行率 · 数据新鲜度
                                                      ▼
        ┌──────────── 证据（数值、能画的图、项目、待办、偏好）────────────┐
        ▼                                                                    ▼
  页面编排（P-Health 写页面 JSON → 服务器校验 → 发布）          对话（P-Health 调命令查数、改待办、记偏好、出跟练片）
        └──────────────────────────────┬─────────────────────────────────┘
                                       ▼
                    iOS App：页面 · 生成式待办 · 对话 · 跟练播放 · 小组件
                    （轮询 /api/v3/status：哪块在改就框住哪块，改好自动换上）
                                       ▲
                    通知线程（服务器里，每 20 秒巡一次）：回复、新问题、待办提前 / 到点 / 过点、计时 → APNs
```

## 定时节拍

| 什么 | 多久一次 | 做什么 |
|---|---|---|
| whoop-sync | 每 15 分钟 | 拉 WHOOP 官方 API；有新的恢复 / 睡眠 / 训练就重排页面 |
| 编排节拍（`scripts/v3-cycle.sh`） | 每天 08:00、13:00、18:00 | 先给主对话发【每日推荐】，P-Health 推荐 1–2 件事（早上那次顺带看昨天、周日那次做周复盘），再重排四个页面 |
| 事件分发 | 每 30 秒 | 先筛：重复位置、蓝牙扫描直接标成已处理；挪动 1.5 km 以上、或其他内容有变化的才合成一轮交给 P-Health 的事件会话 |
| 通知线程 | 每 20 秒 | 服务进程里的后台线程，只对时间、不调用模型；推送失败下一轮重试（最多 3 次），过点 15 分钟内补发 |
| 通知兜底 | 每分钟 | 独立的 launchd 任务跑同一套巡检（文件锁保证不重复推），服务停了也照样提醒 |
| 自检 | 每小时 | 手机在线但健康数据没进库、WHOOP 一直失败、有时间的待办漏推 → 记进 `dev_alerts.jsonl`，不打扰用户 |
| 全盘简报 | 每 10 分钟看一次 | 数据变了才重写工作区的 `CLAUDE.local.md`（DSH 每轮把变了的指令文件补进对话）；只有待办变了最多一小时写一次 |
| 每周对话复盘 | 周一 08:30（和洞察同一个定时） | 收这一周的对话和 👍 / 👎 → 算账 → 写稿校验 → 浮条；同意的改法进记忆或待改清单 |
| 洞察（`scripts/insight-cycle.sh`） | 每天 08:30 看一眼，满 3 天扫一次 | 场景标签 → 找候选 → P-Health 写稿 → 校验 → 存起来等你点开；推送开关默认关，关着时只试算 |

P-Health 自己不建定时任务、不自己推送。要到点提醒的事一律写成带时间的待办卡，由服务器到点推送。

## 分层约束

| 层 | 在哪 | 边界 |
|---|---|---|
| 数据 | `readonly.py`、`whoop.py`、`whoop_sync.py`、`event_ingest.py` | 客观库只读；WHOOP 和 Apple 的同名指标口径不同，一条序列只取一个设备；断更就如实说 |
| 计算 | `sleep.py`、`baselines.py`、`viz.py`、`canvas.py`、`canvas_parts.py`、`coach.py` | 数字只从这里出；常态范围按本人近 30 天算，不是医学标准 |
| 编排 | `v3.py`（证据、校验、发布）、`agent/AGENTS-v3.md` | Agent 只能引用证据里的数，不能自己写数；校验不过的页面不发布 |
| 待办与习惯 | `todos.py` | 待办内容由 Agent 生成；习惯项目按模板每天展开，改模板"今晚起"生效；练习只认跟练工具出的片 |
| 对话卡片 | `cards.py` | 发卡前格式检查；坏卡片记进日志 |
| 偏好与记忆 | `prefs.py`、`agent_context.py` | 一份共享记忆，页面编排和对话都读它；偏好、纠正、了解到的你单独写进工作区的 `AGENTS.local.md`（DSH 按文件刷新，记偏好不用重发整份规则） |
| 洞察 | `insight.py`、`insight_cross.py`、`journal.py`、`scene.py` | 候选和数字只由代码算，样本不够不出；稿子过校验才存；只说"常一起出现"不说"导致"；场景只给模型标签 |
| 简报与反馈 | `brief.py`、`goals.py`、`plan_lint.py`、`feedback.py`、`review.py` | 简报的数和交叉信号由代码算；计划冲突由代码查；复盘稿过校验才存，改规则、资料要老大同意并先考题 |
| 通知 | `notify.py`、`apns.py` | 每件事只推一次；每张卡可以改提醒方式（`remind`）；P-Health 没写时间的卡由 `timedraft.py` 拟一个并推送请用户确认；模拟、演示、测试环境不推 |
| 数据连接状态 | `datastatus.py`、`ingest.py` | 分清原因（要用户动手 / 服务器的问题 / 手机没开 App），只有要用户动手的才提示 |
| 插件安装 / 配对 | `setup.py`、`pairing.py`、`dsh/cordis.patch.yml`、`bin/phealth` | 一条命令建目录、配置、DSH 专用 profile 和 launchd 任务；配对二维码；服务器 `/dshp` 凭密钥转发 DSH（HTTP + WebSocket） |
| 康复 / 营养 | `rehab.py`、`nutrition.py` | 伤病档案、疼痛记录和红黄绿灯；营养目标、手掌份量换算成范围、日 / 周汇总 |
| 跟练 | `follow.py` → pivis-follow | 先读懂视频、方案卡确认后才出片；成片只经自己的服务器给 App |
| 接口 | `web.py`、`cli.py` | App 走 HTTP（要设备密钥，本机直连除外）；Agent 走 `./pivis-health` 命令 |
| 示例与测试 | `examples/`、`tests/` | 只用合成数据，不连接真实健康库 |

## 不公开 / 不入库

- 本机配置（`config.local.json`）、地址、APNs 密钥、WHOOP 凭据和令牌、App 设备密钥。
- 真实健康数据库、WHOOP 快照、场景事件、餐照与试纸照片、聊天记录。
- 博主原片和跟练成片。
- 带个人信息的 Agent 规则附录（`agent/AGENTS-real.md`）。
- 安装包（`install/*.ipa`）。
- 封版测试套件（对话用例里带个人健康背景，只在本机）。

## 不做的事

- 不做疾病风险、身体年龄或临床效果的验证声明。
- 不把工程上的异常筛选说成诊断。
