# exercises-dataset 对 P-Health 的价值与接入方案

核对日期：2026-11-12。研究对象是同名项目中最贴近反馈描述的
[hasaneyldrm/exercises-dataset](https://github.com/hasaneyldrm/exercises-dataset)。
核对版本：`7455efae41b330c265e7cd4b78dfa848e7ce5ebd`。
只下载并检查 JSON 元数据，没有下载或引入图片、GIF。

## 结论

推荐先把它接成 **Agent 可检索的动作知识索引**：识别动作、按器材找候选、
整理待确认的视频方案、关联本机已验收的示范。继续由 P-Health 结合个人情况、
专业资料和反馈选动作；数据集不直接生成康复处方。

它对力量训练和动作检索有直接价值，也能减少“每次必须先找视频才知道有什么动作”的工作。
它不能直接解决当前跟练出片耗时：里面的 GIF 不是完整课程，没有讲解、报数或本产品的验收信息。

## 怎么结合

### 第一步：动作检索与素材关联

1. 固定上游版本，离线导入文字数据，保留稳定的上游 ID、来源、许可和更新日期。
2. 增加经校对的中文名、同义词与器材词表；中文指令中的“名字提及”不当成中文名直接截取。
3. 提供 `exercise-search` / `exercise-show` 工具，让 Agent 按部位、器材、名称查候选。
4. 输出候选和依据，不自动增加训练量、不自动改个人计划；专业限制由现有档案及专业资料提供。
5. 将确认过的动作 ID 关联到本机 follow 动作 ID、出处和验收版本。
   已有可用示范时优先复用，缺少时再找素材并走确认流程。

例如：用户说“家里只有弹力带，换个练臀的动作”，先从索引筛出相关候选，
再结合用户伤病、目标、现有负荷和已验收素材决定推荐，最后给方案卡确认。

### 第二步：辅助跟练剪辑

在视频分析后，用索引帮助统一动作名字、找到可能的同义动作，检查方案是否漏动作。
只做候选匹配，保留置信度与原片证据；不同器材、动作变式、单侧 / 双侧不自动合并。
不根据文字说明凭空产生原片中不存在的示范。

### 第三步：按实际效果调整候选顺序

关联用户执行记录、主观反馈和现有康复监控，逐渐知道哪些已确认动作更容易坚持、
哪些不合适。Agent 提出替换，用户确认后改计划；数据集本身不提供个体疗效证明。

## 接入前的验收点

- 中文名和同义词检索能找到同一稳定动作，器材过滤不会混入不具备的器材。
- 不凭肌群相同把两个变式认作同一动作；匹配不确定时能够拒绝并继续查证。
- 没有个人适用性资料的候选不会被说成“适合你的康复动作”。
- 导入和返回数据不含独立授权媒体，保留 MIT 许可和来源。
- 查库、候选卡、确认、复用示范、排计划到反馈能走通闭环。

本次完成研究和方案，尚未导入动作库或改变现有训练计划。
