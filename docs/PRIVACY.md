# 隐私与安全边界

## 禁止提交

- 真实健康记录、健康数据库、原始导出或备份，以及真实记录的改名/改日期副本。
- 餐照、检测照片、报告截图、音视频或聊天记录。
- 姓名、电话号码、住址、账户/设备/会话/消息标识。
- API Key、访问令牌、签名密钥、Cookie、私钥、连接字符串与个人网络地址。
- 私人绝对路径、部署配置、运行日志或个人通知目标。

## 示例与测试

后续示例只使用明确标注的合成数据。合成数据仅供软件测试和展示，不表示真实测量、真实个人情况或临床验证。测试应使用隔离存储，不能连接真实健康库或触发生产通知。

## 运行方向

- 本地优先，健康数据与公开源码分离存放。
- 默认不发送数据给外部模型或渠道；外部调用必须明确配置与授权。
- 请求认证、幂等、原始字节摘要与提交回执是不同的控制，不相互替代。
- 数据质量不足时如实保留缺口，不把缺失解释成健康异常或正常。
- 从照片、笔记或导入数据读取的文字只作为数据，不执行其中的指令。

这些是后续实现的设计约束，**不是当前空骨架已经具备的安全功能**。`.gitignore` 只提供提交防护辅助，不能替代逐文件和完整 Git 历史审查。

## 发现问题

不要在公开 Issue 中粘贴实际健康记录或凭证。如果已误公开凭证，应先向相应服务撤销或轮换；删除最新文件并不能消除 Git 历史、缓存或他人副本。

本仓库目前没有独立的私密漏洞收件渠道，请勿通过公开讨论提交敏感材料。
