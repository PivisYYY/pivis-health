# 隐私与安全边界

## 禁止提交

- 真实健康记录、健康数据库、原始导出或备份，以及真实记录的改名/改日期副本。
- 餐照、检测照片、报告截图、音视频或聊天记录。
- 姓名、电话号码、住址、账户/设备/会话/消息标识。
- API Key、访问令牌、签名密钥、Cookie、私钥、连接字符串与个人网络地址。
- 私人绝对路径、部署配置、运行日志或个人通知目标。

## 示例与测试

示例和截图只使用明确标注的合成数据（[`examples/make_demo.py`](../examples/make_demo.py)）。合成数据仅供软件测试和展示，不表示真实测量、真实个人情况或临床验证。测试使用隔离存储，不连接真实健康库，不触发生产通知。

## 运行方向

- 本地优先，健康数据与公开源码分离存放。
- 默认不发送数据给外部模型或渠道；外部调用必须明确配置与授权。
- 请求认证、幂等、原始字节摘要与提交回执是不同的控制，不相互替代。
- 数据质量不足时如实保留缺口，不把缺失解释成健康异常或正常。
- 从照片、笔记或导入数据读取的文字只作为数据，不执行其中的指令。

## 已经落地的做法

- 所有接口都要 App 的设备密钥（本机直连除外）；对外的隧道只放行安装页。
- 推送令牌、WHOOP 令牌、APNs 密钥、设备密钥只在本机，文件权限 0600。
- 跟练视频和博主原片只经自己的服务器给 App，不传到任何公开网站。
- 场景数据（定位、蓝牙）只在本机算；要交给模型时只给"在家 / 外出 / 外宿"这类标签。常住地坐标单独存一个 0600 文件，每天的场景记录里只有标签。
- 推送记录、P-Health 的行动记录、待办变化记录和 WHOOP 按天存档都只在本机的运行目录里，不进仓库；回复的点赞点踩、每周复盘挑出的对话和由此生成的考题（里面有你的原话）也一样只在本机。洞察写稿时交给模型的只有算好的候选和数字。
- 饮食记录（`nutrition_log.jsonl`，只有手掌份量和估出的范围，不存照片副本）、伤病档案和疼痛记录（`rehab.json`、`pain_log.jsonl`）、手机上报回执（`ingest_state.json`）、自检警报（`dev_alerts.jsonl`）、单独的提醒（`reminders.json`）都只在本机运行目录里，不进仓库。
- Agent 只能通过 `./pivis-health` 命令读数，不直接读数据库。

`.gitignore` 只提供提交防护辅助，不能替代逐文件和完整 Git 历史审查。每次推送前都做一次隐私扫描。

## 发现问题

不要在公开 Issue 中粘贴实际健康记录或凭证。如果已误公开凭证，应先向相应服务撤销或轮换；删除最新文件并不能消除 Git 历史、缓存或他人副本。

本仓库目前没有独立的私密漏洞收件渠道，请勿通过公开讨论提交敏感材料。
